HOW I WORK

先把问题问对，
再用最小闭环验证。

我不太相信「先画完所有页面再找用户」。更有效的顺序是：找到一个真实卡点，做一条能跑通的主路径，尽快让真实的人用起来，再补边界。

01

找真问题

问卷、访谈、竞品和场景拆解一起用。不把「用户说要一个功能」直接当需求，而是追到他真正想完成的事。

证据：哒乐星需求调研 / 漫画学雅思用户定位
02

收敛最小闭环

先跑通一条主路径，再补异常和边界。把规则、状态和失败路径写进产品，而不是留给开发临场决定。

证据：挪啦双触发 / 哒乐星举报处置 / 芽芽 ADR
03

用证据说话

每个阶段都要有可检查的产出：可点原型、真机安装包、应用商店上架、用户数、自动化测试。

证据：上架、内测包、49 个单测、48h Demo

01CAMPUS SOCIAL · ANDROID

哒乐星 StarFun

大学生找搭子，不该靠群里刷屏。

蒲公英内测 · 可体验
身份项目发起人 / 产品负责人
时间2025 — 至今
关键词LBS · 社区 · 信任机制
团队产品 / 设计 / 开发协作

问题

想找人打一场球、去图书馆自习，发在群里常常没人回；表白墙的信息又很快沉底。陌生人组局，还多了一层「靠不靠谱」的顾虑。

判断

缺的不是又一个信息流，而是一个「低压力发起 + 可验证身份」的线下组局入口。地图解决「现在附近有谁」，活动解决「这周末做什么」。

我做的

  • 用户调研与场景拆解，收敛出「找搭子」「组活动」双核心场景
  • 设计地图、广场、消息、我的 4 个主 Tab 与发布入口：地图发现 → 发布 → 报名 → 群聊
  • 把实名 / 学校认证、信用与举报处置做成产品规则，而不只是协议文案
  • 跟开发做版本拆解、真机验收，并推进官网、备案、软著与上架材料

关键设计与取舍

01
双入口，而不是单信息流

地图承接即时需求，活动承接计划性需求；两者共用一套报名和群聊链路。

02
认证分层，避免首屏劝退

先可浏览，再轻认证，关键动作前完成学校 / 实名认证，把信任成本放在正确的时刻。

03
把「信任」写进流程

举报 → 处置 → 复核 → 通知，每一步都有状态、责任人和出口，而不是一句「审核中」。

结果

产品已走到可安装的 Android 内测阶段，完成账号、认证、群聊、举报等模块，并经过多轮真机验收。

4 个主 Tab + 发布多轮真机验收官网已上线备案 / 软著 / 安全评估

复盘

社交产品最难的从来不是把功能做出来，而是让用户敢迈出第一步。下一步我会把注意力放在「首场活动的成功率」，而不是日活数字。

02UTILITY · ANDROID

挪啦

重要短信，不该被 99+ 淹没。

Android 已上架 · 2,000+ 用户
身份联合发起人 / 产品
时间2026.02 上架
关键词效率工具 · 通知 · 上架
结果2,000+ 累计用户

问题

违停挪车、工单、航班变更这些短信，经常被 99+ 的消息淹没。用户不是没看到，而是没意识到它重要——等发现时，损失已经发生。

判断

把「所有通知」做成降噪不现实。更小、更可控的切口是：让用户自己定义「什么算重要」，再用足够强的提醒把这条信息送到他面前。

我做的

  • 定义「关键词 + 发件号码」双触发规则，覆盖违停、工作、家人、灾害等场景
  • 设计全屏弹窗 + 铃声 / 震动 + 最近提醒记录的完整提醒链路
  • 做权限引导与使用帮助，降低监测开启门槛，减少「装了但没开」
  • 负责软著、隐私、上架材料与多渠道推广，把产品真正送到用户手里

关键设计与取舍

01
用户自定义，而不是平台猜

重要与否交给用户设置关键词和号码，减少误判，也降低隐私解释成本。

02
强提醒，但必须可退出

全屏预警配明确的关闭与「停止监测」路径，避免工具变成打扰。

03
用一个高频场景做传播

先打「违停挪车」这个强需求瞬间，再扩展到工作、家人与灾害预警。

结果

2026 年 2 月安卓应用商店上架，累计用户突破 2,000；完成软著、备案与多商店素材，关键词模板覆盖多个真实场景。

Android 上架2,000+ 用户软著 / 备案多商店素材

复盘

工具产品的增长不是靠功能列表，而是靠一个「被需要」的瞬间。挪车短信就是那个瞬间；下一步要把「第一次设置」的成功率做得更高。

界面与提醒链路

自定义关键词，到全屏预警——每一步都为「别错过」服务。

03LEARNING · WECHAT MINI PROGRAM

漫画学雅思 / 芽芽英语

不急着背单词，先读懂一个故事。

微信小程序 v0.4 · 原型可体验
身份产品负责人 / 独立设计
时间2026.10 — 至今
关键词学习闭环 · 内容结构 · 交互
阶段待真机 / 审核

问题

5–6 分的考生往往单词背了不少，但读长句还是慢，读完记不住。传统背单词产品把词从语境里抽走，迁移不到阅读。

判断

提分的关键不是词汇量，而是「在语境中快速识别词块」。漫画提供连续情境、人物和情绪，能让一个表达被记住更久，也更愿意读下去。

我做的

  • 用户与竞品调研，确定「漫画阅读 → 四维训练 → 延迟复习」的学习闭环
  • 写 MVP 规格与 12 条 ADR，完成 7 个页面与可点击原型
  • 设计 5 张分镜 / 10 句对白 / 6 个目标表达的内容结构
  • 组织开发与验收：49 个单测、14 步自动化冒烟、1.8MB 包体

关键设计与取舍

01
一话只锁 6 个表达

少而深。按「表达 × 词义 / 拼写 / 搭配 / 阅读」记录掌握度，不做过关式假掌握。

02
点气泡 = 单句播放 + 中文

把「听不懂」拆成可重试的小步骤；长难句只在角落给低干扰入口，不打断阅读。

03
首版零第三方 SDK、零埋点

先验证学习闭环，再谈增长和商业化。数据只存本机，降低合规与信任成本。

结果

已有一个可运行的原生小程序 v0.4 竖切片：从首页到复习完整跑通，并通过自动化质量链；目前待真机与审核。

7 个页面49 个单测14 步冒烟1.8MB 包体

复盘

学习产品最大的诱惑是不断加内容。我用 ADR 把「不做什么」写下来：先让一话被读完、被复习，再谈六话和付费。

打开可交互原型 ↗ 项目说明 / 源码

学习旅程

手机打开原型是全屏体验；桌面打开是带设计说明的手机预览。

04AI · HACKATHON MVP

金灵酒鬼

拍一瓶酒，AI 帮你识酒、调酒、配菜、组局。

抖音创变者黑客松 · 48h MVP
身份队长 / 产品 + 前端
时间2026.06 · 48 小时
关键词AI 应用 · 人格化 · 降级
团队2 人

问题

想喝点好的，但看不懂酒标、不会调、不会配菜；搜到的内容不是百科就是广告，看完仍然不知道今晚该怎么喝。

判断

用户要的不是知识库，而是一个「懂酒的朋友」，在三分钟内给出一套能执行的方案：这瓶酒是什么、怎么调、配什么、怎么组局。

我做的

  • 2 人团队 48 小时：需求收敛、信息架构、交互原型、前端与路演
  • 定义「女调酒师」产品人格与语气边界，让 AI 输出稳定、可信任
  • 设计识酒 → 调酒 → 配菜 → 酒局邀请的完整演示链路
  • 做 AI 失败降级：接口不可用时自动切 Mock，保证现场演示不中断

关键设计与取舍

01
人格先行，再写提示词

先定义「她怎么说话」，再拆专业字段与个性表达；专业信息克制，语气统一。

02
演示优先，砍掉非核心

核心链路必须 3 分钟讲完；历史记录、复杂设置等全部让位于现场体验。

03
失败路径也是产品

AI 超时或识别失败时，给明确反馈并切换到可用结果，而不是空白或报错。

结果

48 小时完成可演示的 Web MVP，覆盖识酒、调酒、配菜、酒局 4 段流程，并沉淀 MVP 需求书、部署文档与 GitHub 仓库。

48 小时2 人团队4 段流程GitHub 开源

复盘

黑客松教会我的不是「做得快」，而是「先决定不做什么」。如果重来，我会更早把「识酒准确率」的预期管理写进界面。
